# 交付问答验收

使用当前真实 API、真实模型和知识库运行问题。标准答案留在本地评测端；只将 question（或连续追问的当前一句）发送给接口。评测问题、gold_answer 和本目录报告不要上传到知识库。

```sh
uv run --project backend python backend/scripts/evaluate_delivery.py --output eval/reports/my-run
```

需要先按 README 启动 API、前端依赖和已有制度知识库；workers 默认 2，上限 2，避免压满聊天并发。每题单独会话，记录文本、来源、检索、耗时、增量次数与错误；完成后只清理该次创建的会话。运行会产生真实模型、搜索与追踪调用。

当前样本 [delivery-cases.jsonl](delivery-cases.jsonl) 共 20 题：制度与数值边界、跨文档、拒答、通用、澄清、图片、联网和连续追问。来自独立 50 题资料的选题及少量能力验证题，未修改原始语料。

| 记录 | 结果与含义 |
| --- | --- |
| [首轮](reports/2026-11-15-first-run/README.md) | 基本检查 15/20；发现过度澄清、引用格式波动，以及一项要求了题目未询问内容的检查规则。 |
| [修复后复跑](reports/2026-11-15-final-run/README.md) | 基本检查 19/20；剩余一题返回数字引用列表，触发原来的对象格式校验。 |
| [引用兼容复验](reports/2026-11-15-citation-recheck/README.md) | 剩余题在兼容后复验 1/1；仍校验有效编号、实际正文引用和原文。 |
| [逐题核对](reports/2026-11-15-final-run/review.md) | 对实际问题、答案和引用逐题复核，明确使用复验结果的题目。 |

基本检查只验证路由、引用、拒答及少量关键事实，不等于总体语义准确率。不能把“19/20 + 1 次复验”描述为首次运行 20/20，也不能据此宣称完整 50 题全部通过。
