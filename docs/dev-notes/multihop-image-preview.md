# 两跳证据、Word 预览与图片制度

2026-11-15 完成。本阶段保留现有文档、会话标识与正式图谱，继续只验收电脑端。

## 可体验内容

- 问答工作台自动尝试图谱证据扩展；“检索详情”保存实际路径、起点/目标原文、适用条件及目标来源是否被最终引用。刷新后可回看，不重新执行检索。
- DOCX 的“文档原件”使用按需加载的 `docx-preview`，支持放大、缩小及适应宽度；正文与切块仍可使用。浏览器排版不保证与 Word 的分页、字体完全一致。
- 支持 PNG、JPG/JPEG 上传。图片通过 MinerU OCR 后进入同一切块、向量、混合检索、问答与引用链路，原图可预览和缩放；单张图片按原件第 1 页定位。

## 实现约束

图谱扩展沿固定的 `规则 → 引用制度 → 目标规则` 两条实际关联运行，不生成任意 Cypher，不把共享岗位当作额外审批关系。最多取 30 个融合候选作为起点；优先匹配问题点名的制度，对原文规则排序后检查最多 4 条路径、6 个目标切块。目标候选合并后复用原来的预算与单次重排。

每个路径端点必须属于本轮已发布文档快照，并重新核对真实块定位、逐字引文、数字、否定和时序条件。金额/工作日范围按明确数值检查边界；“半天”可匹配工作日档位，小时不会自动换算成天，区间问题和其他不明确条件保持未决，交给原文约束回答。显式文档范围、更新来源和删除来源不能被图谱扩展绕过。

图谱不可用时保留普通检索并显示降级。来源已在融合候选中时会如实显示新增 0 个；只有图谱发现的候选不填造 RRF 分数或融合排名。路径显示目标来源的最终引用状态，不能据路径本身补编未规定的事实。

`POST /api/search` 可显式传 `use_graph: true`；默认 false 便于保留基础检索对照。聊天自动启用有界图谱扩展，无图谱时正常检索。暂未增加单独的模式管理页面。

图片保留 20 MB 原件上限，新增真实解码、扩展名/内容匹配及 4000 万像素检查；JPEG 统一存为 `jpg`。迁移 `0003_image_documents` 只扩展格式约束，原标识和数据保留；存在图片时降级迁移会拒绝缩窄约束，避免丢数据。暂不支持 WEBP、TIFF、HEIC 或把多张图片自动合成一本资料。

Word 在独立 Shadow DOM 中渲染，禁用 HTML altChunk 和嵌入字体加载，限制超链接协议。它提供原件内容核对，不能替代办公软件编辑或精确打印。

真实验收还发现一次模型没有返回有效 JSON，修复为千问有据回答显式请求 JSON object；三方提供方保持原接口参数。无效 JSON 可在原消息上手动重试，沿用最多 3 次尝试的限制，不新增重复历史、不自动重放生成。

## 验收结果

| 场景 | 结果 |
| --- | --- |
| 用户提供的 `制度 01.png` | 真实上传、MinerU OCR 和索引完成：1 页、14 个内容块、6 个切块 |
| 原图关键事实 | 10 个工作日、次月第 5 个工作日且取较早期限、500 元例外、批量/重复采购例外、90 天要求均识别到 |
| 图片问答 | 正确说明并非所有 500 元以内办公用品都可直接报销，批量/重复采购须先走采购流程；实际引用包括该 PNG 第 1 页 |
| DOCX 原件 | 实际采购制度显示标题、正文及表格，缩放/适应宽度可用 |
| 员工手册 → 考勤制度 | 线上聊天保存 1 条“不超过 1 个工作日请假审批”路径，目标来源被实际引用，回答直属主管审批 |
| 员工手册 → 报销制度 | 真实模型对照显示电子发票须为原始 PDF/OFD，截图不能替代；保存实际制度引用路径 |
| 培训事前审批岗位缺失 | 明确回答制度没有写明具体岗位，未使用报销审批角色替代 |

基础 RAG 与图谱增强使用相同问题、来源格式和回答系统提示分别生成，并保存答案、引用、候选和耗时。两题的基础 RAG 原本已命中关键资料，最终增强结果也没有新增融合候选；本轮证据支持路径核对，不能据此认定整体准确率或速度提升。对照是固定问题的生成验证，线上聊天另验意图路由及持久化。

- 后端全量（含真实隔离 PostgreSQL/Neo4j）：257 项通过。
- 前端 53 项、Node 22 构建、Ruff、Alembic check 和差异检查通过。图谱/PDF 的既有分包大小提示仍存在，阅读器按需加载。
- 1280×720、1440×900：Word/图片预览、缩放、图谱路径展开、目标原文高亮及刷新恢复；无页面横向溢出。
- 现有四份制度图谱保留，新增图片可通过图谱页手动生成，上传不会自动进行图谱抽取。
