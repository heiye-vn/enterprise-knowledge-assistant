# 电脑端界面优化

2026-11-15。对应增强待办第二项；按用户最新要求，只以电脑端使用与录屏验收为目标，不安排手机端适配。

## 交互调整

- 全局操作提示移至顶栏下方居中，不再覆盖底部输入框。成功、信息、错误使用不同图标和颜色；支持手动关闭、四秒自动关闭。连续触发同一条提示也会重新计时，错误保留 `alert` 语义。
- 欢迎区上传按钮统一横向排列图标与文字；增加说明与按钮间距，欢迎区在可用聊天区域内居中，输入区独立保留高度。
- 正文统一行距、字号、颜色和段间距；会话标题、来源名称与长内容保持在各自区域内。
- 答案通过 `react-markdown` 和 `remark-gfm` 安全渲染标题、强调、列表、表格和代码。禁用原始 HTML，不加载回答内的远程图片，仅保留 HTTP(S)/mailto 链接。表格和长代码局部滚动，不撑宽整页。
- 已校验来源编号仍可点击；代码及既有链接中的编号保持原样，未知编号保留文本，不生成无效来源按钮。
- 文档正文和切块标题中的 Markdown 强调正常显示；切块正文仍展示实际存储内容，方便核对。
- 1440px 及以上使用 400～470px 并排来源面板；较窄电脑窗口使用 460px 抽屉。面板独立滚动，引用高亮保留。
- 已恢复的处理中消息自动轮询，文案与行为一致；重试时避免同时显示两份等待提示。失败恢复沿用上一阶段原消息受控重试。

## 验证

- 前端原有 37 项加安全 Markdown/引用相关 4 项，共 41 项通过；Node 22 下 TypeScript 与 Vite 构建通过。
- 桌面检查 1280×720、1366×768、1920×1080：无页面横向溢出；输入区可见，按钮内图标文字横向排列。
- 1280×720 的提示顶部为 88px、底部 142px，输入框顶部约 546px，不重叠；关闭按钮与自动关闭实测。
- 用临时、明确标记的排版样本检查列表、表格、长代码、拒答、长会话标题和引用。样本不是模型输出或效果评测；来源使用现有员工手册实际切块，引用通过现有持久化校验。
- 已验证正文定位高亮、16 个实际切块和切块高亮。桌面来源抽屉不压缩聊天区，宽屏并排展示。
- 浏览器本轮观察到的控制台无错误或警告。全部 1 个临时会话、6 条临时消息及对应引用已按登记 ID 清理，用户文档、会话和 `test-data/` 未改动。
- 构建保留已有 PDF 阅读器包体积提示，功能不受影响。本阶段未修改后端或重新做模型质量评测。

本机验收图片与临时脚本位于被 Git 忽略的 `.local/layout-qa/`。后续进入意图识别、澄清和检索详情，继续按增强待办推进。
