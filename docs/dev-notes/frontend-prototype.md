# 前端交互原型

日期：2026-11-13。范围：`frontend/src/`、`frontend/public/demo/` 与前端构建配置。该模块用于确认视觉与交互，不代表后端或模型集成已完成。

## 设计与范围

用户选择浅色、简洁、突出问答和原文。顶部导航切换问答工作台、文档管理和知识图谱，左侧内容随当前页面变化，右侧用于原文溯源。窄屏侧栏与原文面板改为抽屉。

侧栏不按当前四份示例文档设计为常驻文件列表，而按页面任务分配职责：

- 问答工作台：新建会话、历史会话搜索、会话切换；新问题自动作为会话标题，会话内容与问答范围在本次页面内分别保存。
- 文档管理：全部文档、动态分类、分类搜索、处理状态筛选。正文区域提供文档搜索、可移除的筛选条件、分页和每页条数；上传入口集中在文档管理页。
- 知识图谱：当前主题的节点搜索、主题切换、文档/事项/规则/岗位/材料五类节点筛选。ECharts 按力导向布局呈现局部图，初始只显示主题根节点的一层关联；可展开所选节点或当前视图的一层关系，也可收起重置。搜索优先定位名称完全匹配的实体，同时保留其一层关联。节点和关系的详情均提供来源条款入口；下方折叠列表支持键盘选择。图谱仍为预置关系示例。

问答范围移至输入框底部，默认“全部知识库”，可在弹窗内搜索、按分类筛选并分页选择指定文档；只对当前会话后续问题生效。新上传的演示文件仍不能参与问答。切换顶部页面时收起原文面板，避免展示上一页的证据内容。

React + TypeScript + Vite + Tailwind CSS；Lucide 提供统一图标。PDF 使用 react-pdf，图谱使用 Apache ECharts 6.1.0 的 graph 力导向布局，均按视图延后加载。当前使用组件状态展示固定场景，尚未接入 AI SDK useChat 或真实流式接口。

上传只读取文件选择结果的名称和大小并演示任务阶段，不发送原件、不解析、不建立索引。新导入演示文件不能被选为问答来源。未知问题明确提示尚未接入真实服务，不能把该提示算作 RAG 拒答。

## 实际遇到的问题

### 【实录】样式导入的 TypeScript 声明

现象：第一次构建出现 `TS2882: Cannot find module or type declarations for side-effect import`，涉及应用、React Flow 和 react-pdf 的 CSS。

原因：手工初始化时缺少 Vite 客户端环境声明，TypeScript 无法识别样式模块。

解法：新增 `frontend/src/vite-env.d.ts`，引用 `vite/client`，保留严格类型检查。

验证：从根目录运行 `pnpm --dir frontend build`，TypeScript 与 Vite 构建通过。

### 【实录】当前 PDF 与先前文本缓存版本不同

现象：实际 PDF 阅读器显示制度版本 1.1，旧文本缓存仍是 1.0；员工手册现在有 5 页，发票条款、培训条款已移到第 4 页。

原因：先前审阅生成的文本缓存不能代表当前原件快照。

解法：直接读取当前四份 PDF 重建演示正文和元数据，逐条确定引用页码，保存文件 SHA-256。条款编号不代替页码；展示版本从文档元数据读取。

验证：四个引用片段在去除排版空白后均能在指定原件页找到；演示副本与原始 PDF 的哈希一致；浏览器已打开员工手册第 2 页、报销制度第 4 页核对。

| 引用 | 文档 | 当前页码 |
| --- | --- | --- |
| 第十一条，申请审批流程 | 考勤与休假管理制度 | 3 |
| 第九条，考勤与请假 | 员工手册 | 2 |
| 第十条，发票要求 | 费用报销管理制度 | 4 |
| 第二十三条，培训 | 员工手册 | 4 |

### 【实录】低高度屏幕的侧栏被压缩

现象：放大字号后，720 像素高的窗口中，侧栏 flex 布局将文档列表压缩到接近一行。

原因：侧栏子项默认允许 flex 收缩，列表先被挤压，未按预期保留阅读高度。

解法：侧栏各区块禁止被压缩，由侧栏滚动承载超出内容。

验证：本地预览的四份文档恢复可读列表；375、768、1024、1440 像素宽度检查中，页面根节点滚动宽度均等于视口宽度。

## 已执行验证

### 适应画布延迟缩放修复（2026-11-14）

- 原因：适应画布按钮递增 `resetKey`，触发 `setOption(..., { notMerge: true })`，重建图谱并重新运行力布局。布局停止后，120 ms 的自动适配任务再次缩放，造成点击后先放大、几秒后又缩小。
- 修复：按钮通过图谱组件的 `fit()` 方法直接调整当前视野，取消待执行的自动适配任务，保留当前节点布局和选择。手动缩放、平移同样取消旧任务；图谱内容或容器尺寸变化后才重新安排自动适配。
- 将视野控制与图谱初始化分开，移除 `resetKey` 对图谱重建的触发。控制器销毁时取消定时器并解除事件监听。
- 新增真实 ECharts 与受控计时器的回归测试，覆盖立即适配且不重建节点、取消延迟二次缩放、手动缩放优先，以及图谱变化后恢复自动适配。全部 20 项测试和 TypeScript / 生产构建通过；未新增浏览器实际点击验证。

### ECharts 关系图替换（2026-11-13）

- 使用 ECharts 6.1.0 的模块化 GraphChart、CanvasRenderer、Tooltip、Aria 与 LabelLayout；画布随图谱视图延后加载。移除 React Flow 的直接依赖与专用样式。
- 图谱数据改为显式节点/关系及来源映射。请假主题保留三个时长档位、两级审批与人力资源部备案；培训主题保留采购适用条件，未编造培训审批岗位。
- 每次最多显示 80 个节点，展开只增加直接相邻的实体。节点详情按钮在“展开关联 / 收起关联”之间切换；收起一个分支时，清理其隐藏下级的展开状态，并保留其他分支仍需显示的共享节点。顶部“收起全部”保留搜索与类型筛选，“重置图谱与筛选”则恢复全部条件。节点用类型名称、颜色和形状区分；关系名称在悬停或选中时显示。
- 普通模式使用异步力布局，保留节点拖动；布局渲染停止更新后，再根据实际图形边界自动缩放、居中。展开、搜索、重置和容器尺寸变化时重新适配，用户拖动时不强制重新适配；选中节点不会重建布局。系统选择减少动态效果时使用静态力布局并禁用节点拖动，保留画布平移、缩放、节点列表和原文操作。窄屏通过 LabelLayout 隐藏重叠标签，完整名称仍可在提示与节点列表读取。
- `pnpm test` 的 13 项图谱逻辑测试与 3 项真实 ECharts SVG 集成测试均通过，覆盖展开/收起往返、共享分支保留、隐藏下级状态清理、搜索上下文、精确名称优先、类型过滤、空状态、251 节点数据的展示上限、图谱越界、拖动回弹与关系选中标签回归。TypeScript 与生产构建通过。
- 使用真实 ECharts SVG 渲染器检查两组主题的初始/展开状态，在 1100 与 330 像素画布中核对节点边界、缩放、选中与来源映射；这些检查不等同于浏览器实际点击验证。
- `pnpm install --lockfile-only --offline --ignore-scripts --frozen-lockfile` 核对清单与锁文件一致。依赖通过本机已有的 pnpm 缓存离线恢复，每个文件校验 SHA-512；没有执行依赖安装脚本。需要重新安装时仍使用普通 `pnpm install --frozen-lockfile`。

## 已知局限与后续

用户已要求暂停后端接入；当前仅保留前端原型供评审，不启动实施计划中的后端任务。

- 问答、短期上下文和图谱只是固定交互样例，没有真实检索或推理能力。
- 切片为原型中的人工摘录；正文提取用于 UI 预览，不替代计划中的 MinerU 规范化管线。审批表展示两列摘要，完整补充要求以 PDF 为准。
- 会话与会话范围仅保存在页面内存，刷新后重置。窄屏抽屉的完整键盘焦点约束、流式中止与错误场景应在真实接口接入时补齐。
- 真实接口接入时使用 AI SDK useChat，并验证结构化引用、完成、中止和错误事件；当前固定示例不能当作流协议测试。
- 语料现在为 1.1，后续评测标注需对照当前文件重新核验，不直接沿用旧版条款结论。
