# 意图识别与检索详情实施计划

目标：完成增强待办第 3、4 项及用户确认的召回打分展示，在现有问答流程中增加澄清和可回看的执行详情。

设计依据：[增强待办](../../roadmap-2026-11-15.md) 与本轮已确认的分数展示方案。直接在当前功能分支单代理执行，不新建工作树、不提交 Git、不修改用户数据或模型配置，只验收电脑端。

- [x] 路由与澄清：扩展现有 `plan_reply` 为 `general / knowledge / clarify`；先写非法输出、企业依据保护、澄清恢复测试，再提取路由模块并接入现有持久化。
- [x] 真实检索详情：先测试实际 PG 检索的分数/排名映射和降级；记录 BM25、向量距离、RRF、所有送入重排候选的分数、阶段耗时及返回数量。候选只保留有限摘要，打开时仍定位固定 job 的实际正文或切块。
- [x] 每轮保存：使用现有 `request_snapshot` JSON 字段保存版本化 `details`；区分融合候选、送入回答模型和最终引用。完成、拒答、失败都保存真实执行阶段，原消息重试重置详情。老消息不伪造历史数据。
- [x] 电脑端详情：默认折叠，展示识别类型、检索问题、耗时、警告、候选排名与分数、实际引用；提供正文/切块入口。前端测试验证缺失分数、降级及旧消息。
- [x] 验收：后端单元与真实隔离数据库测试、Ruff、前端测试与构建；真实模型案例及桌面浏览器核对详情和刷新恢复。仅清理登记的本轮验收会话，更新增强待办和开发记录。

阶段状态使用 `completed / failed / skipped`，未执行不显示耗时为零。分数不是正确率，不生成伪置信度；澄清是正常完成的对话回合，不能冒用文档依据。检索详情来自本轮保存结果，展开或刷新不重新检索。
