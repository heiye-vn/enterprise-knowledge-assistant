# Tavily 联网查询与 LangSmith 追踪

用户已确认上一轮的联网开关、只读单工具、网页来源、阶段/失败展示和知识库依据边界，并补充 Tavily 与 LangSmith 私有配置。沿用当前目录、单代理、不提交 Git、保留 .env 原有设置，按用户追加要求开启内容记录、不引入数据库迁移。

方案：直接使用 Tavily Search REST API；无需部署 MCP，也不新建工具管理平台。每轮默认关闭联网，仅 general 且用户显式开启时执行一次 basic 搜索，最多 5 条结果、20 秒超时；检索 query 经意图调用生成，不发送完整会话或企业文档。knowledge/clarify 继续已有流程，企业制度不使用网页补齐。搜索结果作为不可信引用材料供当前选定模型流式回答；正文及网页引用完整校验后发布。无结果或失败不冒充已联网答案。

LangSmith 通过官方 REST runs 接口上传链路元数据：每个聊天尝试一个根 trace，子 span 覆盖意图、知识检索、Tavily、回答及其实际模型调用。默认仅记录模型名、耗时、Token 数、结果数量和状态，不传原文、问题正文、答案正文、密钥或搜索摘要。后台有界队列发送，追踪故障不影响业务；关闭配置时不发请求。独立网络代理选项按实测配置，遵守现有模型网络设置。

界面复用当前电脑端样式，使用可键盘操作的“联网查询”开关，发送后冻结本轮选择。阶段反馈、最终网页来源及查询时间、工具详情随会话保存；知识库与网页引用外观和语义明确。LangSmith trace ID 在详情中便于核对，不声称上传完成直到实际 API 读取确认。
