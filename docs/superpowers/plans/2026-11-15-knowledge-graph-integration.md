# 正式知识图谱接入计划

设计依据：[图谱小样验证](../../dev-notes/knowledge-graph-spike.md) 和增强待办第 6 项。用户已批准接入任务、接口和页面，单代理在当前功能分支执行，不提交 Git；只验收电脑端。

目标：上传并完成索引的文档可手动生成有来源的真实图谱，异步状态可恢复；复用现有 ECharts 完成搜索、筛选、展开/收起、关系详情及正文/切块跳转。本轮不把图谱用于自动问答。

- [x] `app/graph/extraction.py`：按真实字符/表格行定位生成有限条款单元，固定关系枚举，类型和事项名称由程序生成；校验引用、目标、数字、否定和时序条件。先以独立预期编写并运行失败测试。
- [x] `app/graph/service.py`、`app/tasks/graph.py`：复用 `processing_jobs` 的 graph 类型与 source_job_id，每批保存校验结果到 checkpoint。提取配置和文档目录快照参与指纹；相同请求复用任务，目录变化可复用同一导入结果的已校验抽取记录重新投影。
- [x] `app/graph/store.py`：Neo4j 参数化、事务投影。文档/角色等实体可共享，规则与边属于不可变 projection_id；PostgreSQL 只发布仍持有效租约的投影，过期写入不能覆盖已发布结果。
- [x] `app/api/graph.py`：生成、任务状态与真实图数据。读取仅选当前有效导入的已完成投影；Neo4j 错误明确返回可用性信息，聊天仍可独立工作。所有展示引用从 PostgreSQL 校验快照及真实切块生成。
- [x] dispatch/Celery 接入 graph 类型，沿用 documents 队列。分批续跑不耗重试次数，错误重试有界；Neo4j 重试复用抽取结果，原文变更不发布旧图。
- [x] React 图谱入口和 GraphPanel 改为真实接口，保留 ECharts、80 节点首屏、图例、缩放、搜索、展开/收起和键盘列表。增加进度、部分校验未通过、失败恢复与原文条件，不增加版本/分类管理入口。
- [x] 隔离 PostgreSQL / Neo4j 集成测试覆盖去重、检查点恢复、投影故障、过期租约、来源更新、删除排除及读取降级；前端测试与桌面浏览器验证。再对当前已上传制度执行真实任务并保留正式图谱，仅清理登记的临时验收数据。

约束：不新增业务表或迁移；原始文件、用户会话和 `test-data/` 保留。程序校验不宣称模型语义绝对正确，界面保留原文与条件。有限候选/输入预算以及服务不可用均如实显示，不用静态示例替代实时数据。

验收完成：后端 234 项、前端 52 项测试与构建通过，Ruff / Alembic check 通过；四份正式制度已生成并保留 210 节点、298 关联、96 处来源，重复生成未新增任务。详见 [正式图谱记录](../../dev-notes/knowledge-graph.md)。下一步按增强待办第 7 项接入图谱辅助两跳问答。
