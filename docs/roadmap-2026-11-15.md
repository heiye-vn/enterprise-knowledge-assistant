## 推荐操作演示安排（20 分钟，可压缩至 15 分钟）

| 时段 | 内容 | 可讲解点 |
| --- | --- | --- |
| 0～2 分钟 | 任务目标、页面与技术结构 | 模型回答与企业知识的边界 |
| 2～5 分钟 | 上传、去重、处理状态、正文与切块 | 为什么切块、如何保留来源 |
| 5～9 分钟 | 知识问答、引用、拒答与连续追问 | 混合检索、重排、条件与事实依据 |
| 9～11 分钟 | 意图路由、通用对话、检索详情 | 如何选择调用路径，耗时来自哪里 |
| 11～15 分钟 | 真实图谱与两跳跨文档问题 | 关系来自哪段原文、怎样补全证据 |
| 15～17 分钟 | 已接入的联网/MCP 工具，或质量评测 | 真实工具调用、外部信息与企业制度的边界 |
| 17～20 分钟 | 结果对照、失败处理与启动说明 | 效果、限制、可继续改进的地方 |

只演示已经真实完成且验收的能力。图谱小样验证未通过时，将相应时间用于跨文档检索和评测讲解，不把静态手写图当作模型抽取结果。

## 执行顺序和投入控制

连接修复 → 页面优化 → 意图与检索详情 → 图谱小样 → 真实图谱/多跳 → 流式体验 → 联网或 MCP → 完整验收与录屏。

流式可以在图谱等待云调用时穿插，但不并行修改共享状态。图谱小样和 MCP 探路到预算上限后记录结果并评估继续价值。若开发窗口仅剩一天，优先稳定性、布局、意图/检索详情和验收；图谱、多跳、联网及 MCP 全部完成通常需要数天有效开发时间，不能用 15～20 分钟视频时长推算开发工作量。
